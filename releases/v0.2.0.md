# v0.2.0 — Painel do procurador e API autenticada

**29 de julho de 2026** · marco de desenvolvimento (sem pacote instalável)

## Por que esta versão

A [v0.1.0](v0.1.0.md) só rodava por linha de comando, com os PDFs largados numa
pasta. Serve para desenvolver; não serve para um procurador usar, e muito menos
para o SIAP consumir.

Faltavam as duas portas de entrada — e, no momento em que o sistema deixa de
rodar na máquina de quem o escreveu, faltava também a autenticação. Os
relatórios carregam **nome, CPF/CNPJ e valor de dívida**.

## O que tem de novo

**Painel do procurador.** Página web onde se envia os PDFs, acompanha o
processamento e baixa os relatórios. Protegido por senha.

**API v1.** Para sistemas externos, com autenticação por token Bearer. O
processamento é **assíncrono** por necessidade, não por escolha: o OCR leva
minutos por lote e nenhum proxy mantém uma conexão HTTP aberta tanto tempo. O
envio responde na hora com um `lote_id` e o consumidor acompanha por polling.

**O serviço falha fechado.** Sem `API_TOKENS`, a API recusa tudo com `503`; sem
senha, o painel não abre. Uma configuração incompleta deixa o serviço
inacessível — nunca aberto. É deliberado: o modo de falha de um sistema que
guarda CPF não pode ser "liberar".

## A decisão que dá nome à versão: o ambiente guarda hashes, nunca segredos

Variável de ambiente **não é cofre**. O valor aparece na interface do Easypanel,
em `docker inspect`, em `/proc/<pid>/environ` e em qualquer dump de erro.

Então o serviço não guarda o token nem a senha — guarda o **hash**. Quem ler
qualquer um desses caminhos não consegue autenticar.

```bash
python gerar_credencial.py api siap      # token de um consumidor da API
python gerar_credencial.py painel        # senha do painel do procurador
```

O gerador mostra o **segredo** uma única vez, sem gravá-lo em lugar nenhum, e o
**hash**, que vai para o ambiente do serviço. Perdeu o token, emite-se outro — não
há recuperação, e é assim que deve ser.

**Dois algoritmos, por dois motivos diferentes:** os tokens da API são 256 bits
aleatórios, sem força bruta viável — SHA-256 direto basta. A senha do painel é
escolhida por gente, com entropia baixa e atacável por dicionário — essa usa
**scrypt**, lento de propósito.

**Rotação sem parar a integração:** dois hashes com o mesmo rótulo valem ao mesmo
tempo. Adiciona o novo, avisa o consumidor, espera a troca, remove o antigo.

```ini
API_TOKENS=siap:sha256:<novo>,siap:sha256:<antigo>
```
