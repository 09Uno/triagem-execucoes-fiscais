# v0.1.0 — Os dois agentes, empacotados

**28 de julho de 2026** · marco de desenvolvimento (sem pacote instalável)

## Por que esta versão

A triagem de execuções fiscais era feita processo a processo, no olho. Um
procurador abria o PDF, procurava o valor da dívida, a data de inscrição em
dívida ativa, a última movimentação, e decidia o que fazer. Com milhares de
processos, o gargalo não é a decisão — é a leitura.

Esta primeira versão ataca a leitura, e só ela.

## O que tem de novo

**Agente 1 — extração.** Lê os PDFs de uma pasta, aplica OCR nas páginas
digitalizadas e extrai os dados de cada processo: partes, CPF/CNPJ, CDA, valor
original e atualizado, datas de citação, penhora, vara. Sai em Excel para
revisão e em JSON para repasse, com os mesmos campos nos dois.

**Agente 2 — priorização.** Lê o que o Agente 1 extraiu e ordena o trabalho:
prioridade ALTA / MEDIA / BAIXA, ação recomendada, justificativa e alerta de
prescrição pelo art. 174 do CTN. Entrega um JSON por lote e um Excel acumulado,
já ordenado por prioridade e por valor.

**Empacotamento em Docker.** Um `Dockerfile` único que já traz **Tesseract**
(idioma `por`) e **Poppler** dentro da imagem. É o que torna a instalação
possível fora da máquina de desenvolvimento: OCR depende de binários de sistema
que não vêm com `pip install`, e é o tipo de dependência que costuma consumir um
dia inteiro numa instalação manual.

## Decisão de projeto

A separação em dois agentes não é arbitrária. **Extrair e decidir são
responsabilidades diferentes**, e misturá-las produz um sistema que ninguém
consegue auditar: quando o resultado sai errado, não dá para saber se foi a
leitura do PDF ou o critério de priorização.

Separados, cada um é verificável sozinho — e os critérios de priorização podem
mudar (e vão mudar, quando a PGMS definir o valor de corte oficial) sem tocar na
extração.

## Uso

```bash
docker compose --profile batch run --rm agente1
```

Processa os PDFs que estiverem na pasta de entrada.
